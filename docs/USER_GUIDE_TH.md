# คู่มือการใช้งานระบบบันทึกเวลาเข้าเรียน KMUTNB Attendance

ตรวจสอบล่าสุด: **22 กันยายน 2569**
ขอบเขตเอกสาร: branch `main`, commit `63727b1`

คู่มือนี้อธิบายการใช้งานระบบตั้งแต่เข้าสู่ระบบจนถึงงานของนักศึกษา อาจารย์ และผู้ดูแลระบบ โดยอ้างอิงเมนูและพฤติกรรมจากระบบปัจจุบัน ผู้ใช้แต่ละคนจะเห็นเฉพาะหน้าที่ตามบทบาทของบัญชี และ Backend จะตรวจสิทธิ์ซ้ำทุกครั้งก่อนอ่านหรือเปลี่ยนข้อมูล

> ข้อควรระวัง: ห้ามส่ง access token, รหัส PIN, service key, ภาพใบหน้า, ภาพบัตรนักศึกษา หรือข้อมูลส่วนบุคคลผ่านกลุ่มสนทนาหรือช่องทางสาธารณะ เมื่อแจ้งปัญหาให้ส่งเฉพาะข้อความผิดพลาด เวลาเกิดเหตุ รุ่นอุปกรณ์ ระบบปฏิบัติการ Browser และ Request ID ถ้ามี

## สารบัญ

1. ภาพรวมระบบและบทบาทผู้ใช้
2. การเตรียมอุปกรณ์ก่อนใช้งาน
3. การเข้าสู่ระบบ การนำทาง และการออกจากระบบ
4. คู่มือสำหรับนักศึกษา
5. คู่มือสำหรับอาจารย์
6. คู่มือสำหรับผู้ดูแลระบบถาวร
7. สถานะการเข้าเรียน คะแนน และรายงาน
8. ความปลอดภัยและความเป็นส่วนตัว
9. การแก้ปัญหาเบื้องต้น
10. รายการตรวจสอบก่อนใช้งานจริง
11. คำศัพท์ที่ใช้ในระบบ

## 1. ภาพรวมระบบและบทบาทผู้ใช้

### 1.1 ระบบนี้ใช้ทำอะไร

ระบบบันทึกเวลาเข้าเรียนรองรับงานหลักต่อไปนี้

- ยืนยันตัวตนด้วยบัญชี Google ของมหาวิทยาลัย
- จัดการรายวิชา สมาชิก และเกณฑ์การเข้าเรียน
- เปิดคาบเรียนและสร้าง Dynamic QR ที่เปลี่ยนตามเวลา
- เช็คชื่อด้วย QR และใบหน้าหรือด้วยบัตร NFC ตามวิธีที่ผู้สอนกำหนด
- ลงทะเบียนใบหน้าด้วยภาพบัตรนักศึกษาและ Hybrid Liveness
- ตรวจประวัติและแก้ไขสถานะการเข้าเรียนตามสิทธิ์
- ส่งคำร้องพร้อมข้อความ รูปภาพ หรือ PDF ระหว่างนักศึกษากับอาจารย์
- ออกรายงาน Excel, CSV และ PDF
- ตรวจ Audit Log และควบคุมสิทธิ์ผู้ดูแลชั่วคราว

ในมุมมองผู้ใช้ ระบบประกอบด้วยหน้าเว็บที่เปิดผ่าน Browser หรือ PWA, Backend API สำหรับตรวจสิทธิ์และประมวลผล, และ Supabase สำหรับการยืนยันตัวตน ฐานข้อมูล และพื้นที่เก็บไฟล์แนบแบบ private ผู้ใช้ทั่วไปไม่ต้องเข้าสู่ Supabase Dashboard

### 1.2 บทบาทและขอบเขตงาน

| บทบาท | หน้าที่หลัก | สิ่งที่ไม่ควรทำ |
| --- | --- | --- |
| นักศึกษา (`student`) | ลงทะเบียนใบหน้า เข้าร่วมวิชา เช็คชื่อ ดูประวัติ ส่งคำร้อง และดูโปรไฟล์ | แก้ role ชั้นปี รหัสนักศึกษา หรือข้อมูลการเข้าเรียนของบุคคลอื่น |
| อาจารย์ (`teacher`) | สร้างและจัดการวิชา เปิด/ปิดคาบ ดูผู้เข้าเรียน แก้สถานะ ออกรายงาน และตอบคำร้อง | เข้าถึงวิชาที่ไม่ได้เป็นเจ้าของ หรือเปลี่ยนสิทธิ์ผู้ดูแลถาวร |
| ผู้ดูแลระบบ (`admin`) | ดูภาพรวม จัดการผู้ใช้/วิชา/การลงทะเบียน ตรวจ Log ออกรายงาน และอนุมัติสิทธิ์ชั่วคราว | เปิดเผยข้อมูลส่วนบุคคลหรือใช้สิทธิ์เกินวัตถุประสงค์ |
| ผู้ดูแลชั่วคราว | ใช้งานเมนูผู้ดูแลในช่วงเวลาที่ได้รับอนุมัติและเปิดสิทธิ์ด้วย PIN | เปลี่ยนบทบาทถาวร แทนที่ข้อมูลชีวมิติในขอบเขตต้องห้าม หรือส่งต่อ PIN |

หากบัญชีถูกนำไปหน้าที่ไม่ตรงกับบทบาท ให้หยุดใช้งานและแจ้งผู้ดูแล ไม่ควรพยายามแก้ URL เอง

### 1.3 ลำดับการใช้งานทั่วไป

1. ผู้ดูแลเตรียมบัญชีและกำหนดบทบาท
2. อาจารย์สร้างรายวิชา ตั้งเกณฑ์ และรับนักศึกษาเข้าวิชา
3. นักศึกษาลงทะเบียนใบหน้าเพียงเมื่อระบบแจ้งว่ายังไม่พร้อม
4. อาจารย์เปิดคาบและแสดง Dynamic QR
5. นักศึกษาสแกน QR และยืนยันใบหน้า หรือเช็คชื่อด้วย NFC ในจุดที่จัดไว้
6. อาจารย์ปิดคาบ ตรวจผล และแก้ข้อมูลเมื่อมีหลักฐาน
7. อาจารย์หรือผู้ดูแลออกรายงานตามภาคเรียน

## 2. การเตรียมอุปกรณ์ก่อนใช้งาน

### 2.1 ข้อกำหนดร่วม

- ใช้ URL เว็บไซต์ production แบบ `https://` เท่านั้น
- ใช้ Safari, Chrome, Edge หรือ Brave รุ่นปัจจุบัน
- เปิด JavaScript และ Cookie ที่จำเป็นต่อการเข้าสู่ระบบ
- ใช้เครือข่ายที่ติดต่อ Frontend และ Backend ได้อย่างเสถียร
- ตั้งวัน เวลา และเขตเวลาของอุปกรณ์ให้ถูกต้องโดยอัตโนมัติ
- อนุญาตกล้องเฉพาะเว็บไซต์ของระบบเมื่อมีการลงทะเบียนใบหน้าหรือเช็คชื่อ
- ไม่เปิดกล้องเดียวกันค้างไว้ในแอปประชุมหรือ Browser tab อื่น

ระบบไม่มี Pull to Refresh แบบกำหนดเอง หากต้องการข้อมูลล่าสุดให้ใช้ปุ่ม **โหลดใหม่**, **ลองใหม่**, การนำทางของระบบ หรือปุ่ม Refresh ของ Browser

### 2.2 สำหรับนักศึกษา

- บัญชี Google ของมหาวิทยาลัยที่ได้รับสิทธิ์
- บัตรนักศึกษาที่รหัสมองเห็นครบ ไม่สะท้อนแสง และไม่ถูกบัง
- โทรศัพท์หรือคอมพิวเตอร์ที่มีกล้องใช้งานได้
- แสงด้านหน้าสม่ำเสมอ ไม่ย้อนแสงหรือมืดเกินไป
- จอของอาจารย์ที่กำลังแสดง QR ปัจจุบัน ไม่ใช้ภาพ QR เก่า

### 2.3 สำหรับอาจารย์

- ตรวจว่ารายวิชา ภาคเรียน ปีการศึกษา Section และเกณฑ์ถูกต้อง
- เตรียมจอสำหรับแสดง QR ให้เห็นชัดจากตำแหน่งนักศึกษา
- ตรวจเครือข่ายก่อนเปิดคาบ และควรมีอุปกรณ์สำรองสำหรับ NFC หากเปิดใช้
- ส่งออกรายงานสำรองก่อนลบรายวิชาหรือเปลี่ยนรอบรายงานครั้งสำคัญ

### 2.4 สำหรับผู้ดูแลระบบ

- ใช้เครื่องส่วนตัวหรือเครื่องที่ควบคุมได้ หลีกเลี่ยงคอมพิวเตอร์สาธารณะ
- ตรวจชื่อและบทบาทก่อนเปลี่ยนสิทธิ์ ลบผู้ใช้ หรือแทนที่ข้อมูลการลงทะเบียน
- ตรวจ Backend health และการเชื่อมต่อ Supabase ก่อนช่วงลงทะเบียนหรือสอบ
- เปิดเผยข้อมูล Log เท่าที่จำเป็นต่อการแก้ปัญหา

## 3. การเข้าสู่ระบบ การนำทาง และการออกจากระบบ

### 3.1 เข้าสู่ระบบด้วย Google

1. เปิด URL เว็บไซต์ production
2. กด **เข้าสู่ระบบด้วย Google**
3. เลือกบัญชีมหาวิทยาลัยที่ได้รับอนุญาต
4. อ่านข้อมูลที่ Google ขออนุญาต แล้วดำเนินการต่อ
5. หลัง Google redirect กลับมายังเว็บไซต์ ระบบจะตรวจ session และเรียกข้อมูลโปรไฟล์
6. ระบบนำไปหน้าของบทบาทโดยอัตโนมัติ

หากเข้าสู่ระบบสำเร็จแต่โหลดข้อมูลไม่ได้ ให้กด **ลองใหม่** หนึ่งครั้ง หากยังไม่ได้ควรออกจากระบบแล้วเข้าสู่ระบบใหม่ ห้ามแก้ด้วย `no-cors` เพราะจะทำให้หน้าเว็บอ่านผล API ไม่ได้

### 3.2 การนำทางร่วม

- ใช้ปุ่มลูกศรของหน้าจอเพื่อกลับหน้าต้นทาง จะรักษาลำดับการทำงานได้ดีกว่าการแก้ URL
- หน้าต่าง Modal ปิดด้วยปุ่ม `X` มุมขวาบนหรือปุ่ม **ยกเลิก**
- กล่องยืนยันการดำเนินการสำคัญจะแสดงเหนือ Modal อื่นเสมอ ต้องอ่านชื่อรายการและผลกระทบก่อนยืนยัน
- ข้อความสีเขียวหมายถึงสำเร็จ สีเหลือง/ส้มหมายถึงคำเตือนหรือรอดำเนินการ และสีแดงหมายถึงไม่สำเร็จหรือเป็นงานเสี่ยง
- บนโทรศัพท์ เมนูอาจอยู่ด้านล่างหรือเปิดเป็น Drawer; บนคอมพิวเตอร์จะใช้ Sidebar

### 3.3 โปรไฟล์ของอาจารย์และผู้ดูแล

ป้ายบัญชีด้านบนสุดของ Sidebar แสดงรูป Google ชื่อ อีเมล และ role กดป้ายเพื่อเปิดโปรไฟล์แบบ Modal และกด `X` เพื่อปิด หากรูป Google โหลดไม่ได้ ระบบจะแสดงอักษรย่อแทนโดยไม่กระทบสิทธิ์บัญชี

### 3.4 ออกจากระบบอย่างปลอดภัย

1. ใช้ปุ่ม **ออกจากระบบ** ในหน้าโปรไฟล์หรือเมนูบัญชี
2. รอจนกลับสู่หน้าเข้าสู่ระบบ
3. หากใช้เครื่องร่วมกัน ให้ปิดทุก tab ของระบบ
4. ไม่ควรปิด tab แทนการออกจากระบบเมื่อใช้อุปกรณ์สาธารณะ

## 4. คู่มือสำหรับนักศึกษา

### 4.1 ภาพรวมเมนูนักศึกษา

| เมนู | ใช้ทำอะไร |
| --- | --- |
| **หน้าหลัก** | เตรียมระบบตรวจใบหน้า สแกน Dynamic QR และดูผลเช็คชื่อ |
| **ประวัติ** | ดูสรุปและรายละเอียดการเข้าเรียนแยกตามรายวิชา |
| **รายวิชา** | ดูวิชาที่ลงทะเบียนและส่งรหัสคลาสเพื่อขอเข้าร่วม |
| **โปรไฟล์** | ดูข้อมูลบัญชี ชั้นปี สถานะใบหน้า/NFC คำร้อง และออกจากระบบ |
| **ลงทะเบียนใบหน้า** | เปิดจากโปรไฟล์เมื่อยังไม่มีข้อมูลใบหน้า |
| **คำร้องถึงอาจารย์** | เปิดจากโปรไฟล์เพื่อสร้าง ติดตาม และตอบคำร้อง |

แถบเมนูด้านล่างจะปรับขนาดให้เหมาะกับโทรศัพท์ เมื่อต้องใช้กล้องเต็มพื้นที่แอป แถบหัวและแถบเมนูจะถูกซ่อนชั่วคราว และกลับมาเมื่อจบหรือยกเลิกการสแกน

### 4.2 ตรวจโปรไฟล์และชั้นปี

1. เปิดแถบ **โปรไฟล์**
2. ตรวจชื่อ อีเมล และ `StudentID`
3. ตรวจข้อมูลการศึกษา ชั้นปี จำนวนรายวิชา และสถานะการสแกนใบหน้า/NFC
4. หากยังไม่ลงทะเบียนใบหน้า ให้กด **ลงทะเบียนใบหน้า**
5. หากข้อมูลตัวตนผิด ให้เปิด **คำร้องถึงอาจารย์** แทนการพยายามแก้ข้อมูลเอง

ชั้นปีเป็นข้อมูลอ่านอย่างเดียว Backend คำนวณจากปีรับเข้าในรหัสนักศึกษา 13 หลักโดยอิงปีการศึกษาปัจจุบัน นักศึกษาเปลี่ยนเองไม่ได้ หากข้อความระบุว่าไม่สามารถคำนวณได้ ให้ผู้ดูแลตรวจรูปแบบรหัสนักศึกษาและปีรับเข้า

### 4.3 เข้าร่วมรายวิชาด้วยรหัสคลาส

1. รับรหัสคลาส 8 ตัวจากอาจารย์ เช่นรูปแบบ `ABCD-2345`
2. เปิด **รายวิชา**
3. กรอกรหัสให้ครบ ตรวจอักษรและตัวเลขที่คล้ายกัน
4. ตรวจรหัสวิชา ชื่อวิชา Section ภาคเรียน และชื่อผู้สอน
5. ส่งคำขอเข้าร่วม
6. ติดตามสถานะคำขอ

| สถานะ | ความหมาย | สิ่งที่ควรทำ |
| --- | --- | --- |
| รออนุมัติ | ส่งคำขอแล้ว แต่อาจารย์ยังไม่ตัดสินใจ | รอหรือยกเลิกหากส่งผิด |
| อนุมัติแล้ว | เป็นสมาชิกรายวิชา | วิชาจะแสดงในรายการและประวัติ |
| ปฏิเสธ | อาจารย์ไม่อนุมัติคำขอ | ตรวจวิชาและติดต่ออาจารย์ |
| ยกเลิก | นักศึกษายกเลิกคำขอที่รออยู่ | ส่งใหม่ได้หากยังมีรหัสที่ใช้ได้ |

รหัสคลาสที่ปิด หมดอายุ หรือถูกหมุนเปลี่ยนจะใช้ไม่ได้ การทราบรหัสไม่ได้ทำให้เป็นสมาชิกทันที อาจารย์ยังต้องตรวจตัวตนและอนุมัติ

### 4.4 ลงทะเบียนใบหน้าครั้งแรก

#### ก่อนเริ่ม

- ถอดสิ่งที่บังดวงตาหรือใบหน้าเท่าที่เหมาะสม
- ให้มีใบหน้าเพียงคนเดียวในภาพ
- เตรียมบัตรนักศึกษาและตรวจว่ารหัสตรงกับบัญชี

#### ขั้นตอน

1. เปิด **โปรไฟล์** แล้วกด **ลงทะเบียนใบหน้า**
2. เลือก **ถ่ายรูป** หรือ **เลือกรูปภาพ** ของบัตรนักศึกษา
3. ตรวจตัวอย่างให้เห็นบัตรครบ ไม่เบลอ ไม่เอียงมาก และไม่มีแสงสะท้อนบังรหัส
4. ส่งภาพให้ระบบ OCR ตรวจรหัสนักศึกษา
5. หากรหัสบนบัตรตรงกับบัญชี ระบบจะเตรียม Face Landmarker และโมเดลตรวจใบหน้า
6. รอจนสถานะขึ้นว่าพร้อม อย่ารีบปิดหน้าหรือเปลี่ยนแอประหว่างโหลดครั้งแรก
7. อนุญาตกล้องเมื่อ Browser ถาม กล้องจะเปิดเต็มพื้นที่แอปและซ่อน Header/Navigation
8. วางใบหน้าให้อยู่กลางกรอบ มองกล้อง และอยู่นิ่งช่วงเก็บ Passive 3 เฟรม
9. ทำคำสั่งสุ่มเพียงหนึ่งอย่างตามหน้าจอ ได้แก่ **กะพริบตาทั้งสองข้าง 1 ครั้ง** หรือ **ขยับใบหน้าเข้าใกล้กล้องเล็กน้อย**
10. กลับมาวางหน้าตรงกลางกรอบเพื่อให้ระบบเก็บ Recovery frame
11. รอ Backend ตรวจว่าเป็นบุคคลเดียวกัน ตรวจ Passive PAD การเคลื่อนไหว เฟรมซ้ำ และสร้าง face embedding
12. เมื่อสำเร็จ ระบบจะแสดงว่าสถานะใบหน้าลงทะเบียนแล้ว

ภาพบัตรและเฟรม Liveness ใช้ประมวลผลระหว่างคำขอ ไม่ได้เก็บเป็นภาพเช็คชื่อถาวร ฐานข้อมูลเก็บ face embedding ที่จำเป็นต่อการจับคู่และผลการตรวจตามขอบเขตระบบ

#### เมื่อไม่ผ่าน

- OCR ไม่พบรหัส: ถ่ายใหม่ให้บัตรเต็มภาพและแสงไม่สะท้อน
- รหัสไม่ตรงบัญชี: ตรวจว่าใช้บัตรและบัญชีของตนเอง
- ไม่พบใบหน้า: จัดตำแหน่งหน้า เพิ่มแสง และอย่าให้คนอื่นเข้ากรอบ
- Liveness ไม่ผ่าน: ทำเฉพาะคำสั่งที่แสดง ไม่ใช้รูปหรือวิดีโอ และไม่ขยับโทรศัพท์แรง
- เตรียมโมเดลไม่สำเร็จ: ตรวจเครือข่าย กดลองใหม่ และรอให้พร้อมก่อนเปิดกล้อง

### 4.5 เช็คชื่อด้วย Dynamic QR และใบหน้า

#### ก่อนสแกน

1. ต้องเป็นสมาชิกของรายวิชา
2. ต้องลงทะเบียนใบหน้าแล้ว
3. อาจารย์ต้องเปิดคาบอยู่
4. หน้าแรกต้องแสดงว่าระบบตรวจใบหน้าพร้อมใช้งาน

#### ขั้นตอน

1. เปิด **หน้าหลัก**
2. รอการเตรียม Face Landmarker ให้เสร็จ ปุ่มสแกนจะยังไม่พร้อมระหว่างโหลด
3. กดปุ่มสแกน QR และอนุญาตกล้อง
4. ระบบเปิดกล้อง QR เต็มพื้นที่แอป ซ่อน Header และแถบเมนู
5. เลือกเลนส์หลังหากต้องสแกน QR จากจอด้านหน้า
6. วาง QR ให้อยู่ในกรอบ ไม่ต้องขยับกล้องเร็ว
7. เมื่ออ่าน QR สำเร็จ ระบบจะตรวจว่า QR ยังใช้ได้ เป็นคาบที่เปิด และผูกกับบัญชีนี้
8. ระบบเปลี่ยนไปกล้องตรวจใบหน้าเต็มพื้นที่ทันที โดย **ไม่ต้องถ่ายบัตรซ้ำ**
9. วางหน้าในกรอบ รอ Passive 3 เฟรม ทำคำสั่งสุ่ม 1 ครั้ง และกลับสู่กรอบ
10. รอผลจาก Backend ห้ามกดส่งซ้ำหรือย้อนกลับระหว่างประมวลผล
11. เมื่อสำเร็จ ระบบแสดงข้อความ เวลา วิธี และสถานะการเข้าเรียน แล้วคืน Header/Navigation ตามปกติ

เสียงหลังอ่าน QR ถูกปิดในระบบปัจจุบัน หากได้ยินเสียง ให้ตรวจว่าเป็นเสียงจาก Browser ระบบปฏิบัติการ หรือแอปอื่น ไม่ใช่เสียงที่ระบบตั้งใจเล่น

Dynamic QR มีอายุสั้นและเปลี่ยนตามช่วงเวลาที่กำหนด ภาพหน้าจอ QR เก่า การส่ง request ซ้ำ หรือการนำ challenge ของผู้อื่นมาใช้ควรถูกปฏิเสธ

### 4.6 ตั้งค่ากล้อง

ปุ่ม **ตั้งค่ากล้อง** แสดงเป็นแผงขนาดกระชับเพื่อไม่บังกรอบสแกน ตัวเลือกจะขึ้นตามความสามารถจริงของอุปกรณ์

- **เลนส์:** เลือกกล้องหน้า กล้องหลัง หรืออุปกรณ์กล้องที่ Browser เปิดให้ใช้
- **ความละเอียด:** ระบบร้องขอความละเอียดที่เหมาะสม แต่อุปกรณ์อาจเลือกค่าใกล้เคียง
- **Focus:** เลือกโหมดโฟกัสเมื่อ Browser และกล้องรองรับ
- **Zoom:** ขยายภาพแบบกล้องเมื่อรองรับ ไม่ควรซูมมากเพราะภาพอาจแตก
- **Sharpness:** ปรับความคมเมื่อ Camera API ของอุปกรณ์รองรับ

ภาพ Preview จากกล้องหน้าจะ Mirror เพื่อให้การเคลื่อนไหวตรงกับความรู้สึกของผู้ใช้ แต่หลักฐานที่ส่งตรวจยังใช้ทิศทางจริง หากเปลี่ยนเลนส์ระหว่าง Liveness ระบบจะเริ่มการติดตามรอบนั้นใหม่

### 4.7 ดูประวัติการเข้าเรียน

1. เปิด **ประวัติ**
2. ใช้ช่องค้นหาด้วยรหัสหรือชื่อวิชา
3. ดูสรุปจำนวนมาเรียน มาสาย ขาดเรียน เปอร์เซ็นต์ขาด และจำนวนคาบ
4. กดรายวิชาเพื่อเปิดรายละเอียดแต่ละคาบ
5. ตรวจวันเวลา สถานะ และวิธีเช็คชื่อ เช่น ใบหน้า, NFC หรือบันทึกโดยผู้สอน

หากสถานะไม่ตรงกับเหตุการณ์จริง ให้เก็บหลักฐานที่เหมาะสมและส่งคำร้องถึงอาจารย์ ไม่ควรส่งภาพใบหน้าหรือ token เป็นหลักฐาน

### 4.8 ส่งคำร้องถึงอาจารย์

1. เปิด **โปรไฟล์** > **คำร้องถึงอาจารย์**
2. กด **คำร้องใหม่**
3. เลือกรายวิชา
4. ระบุหัวข้ออย่างน้อย 3 ตัวอักษรและอธิบายรายละเอียด
5. แนบไฟล์เมื่อจำเป็น แล้วตรวจตัวอย่างก่อนส่ง
6. กด **ส่งคำร้อง**
7. เปิดรายการเดิมเพื่อติดตาม ตอบกลับ หรือส่งไฟล์เพิ่มเติม

รองรับ PDF และภาพ JPG, PNG, WebP, GIF, BMP, TIFF, AVIF, HEIC/HEIF และ ICO ไม่รับ SVG แนบได้ตามจำนวนที่หน้าจอกำหนดและไฟล์ละไม่เกิน 10 MB ภาพจะถูกแปลงเป็นภาพนิ่ง JPG/PNG และลบ metadata ก่อนเก็บใน private Storage

สถานะ **กำลังดำเนินการ** หมายถึงอาจารย์ยังตรวจอยู่ ส่วน **เสร็จสิ้น** หมายถึงอาจารย์ปิดเรื่องแล้ว หากนักศึกษาส่งข้อความใหม่ ระบบสามารถเปิดคำร้องนั้นอีกครั้ง

### 4.9 ออกจากระบบ

เปิด **โปรไฟล์** เลื่อนไปด้านล่าง กด **ออกจากระบบ** และรอจนกลับหน้า Login หากปุ่มแจ้งว่าไม่สำเร็จ ให้ตรวจเครือข่ายแล้วลองใหม่ ไม่ควรปล่อยบัญชีค้างบนเครื่องผู้อื่น

## 5. คู่มือสำหรับอาจารย์

### 5.1 ภาพรวมเมนูอาจารย์

| เมนู | ใช้ทำอะไร |
| --- | --- |
| **รายวิชาที่สอน** | สร้างวิชา ดูแบบ Grid/List และเข้าสู่ศูนย์จัดการรายวิชา |
| **รายงานการเข้าเรียน** | เลือกรายวิชาและส่งออกรายงาน |
| **ตั้งค่าระบบ** | เปิดคำร้อง สิทธิ์ผู้ดูแลชั่วคราว และข้อมูลระบบ/ความปลอดภัย |
| **ป้ายโปรไฟล์** | ดูรูป Google ชื่อ อีเมล และ role แบบ Modal |

Sidebar ยุบหรือขยายได้ บนคอมพิวเตอร์ที่มีเมาส์ Sidebar ที่ยุบจะขยายชั่วคราวเมื่อชี้ บนโทรศัพท์จะเปิดเป็น Drawer และปิดหลังเลือกเมนู

### 5.2 สร้างรายวิชา

1. เปิด **รายวิชาที่สอน**
2. กด **เพิ่มรายวิชาใหม่**
3. กรอกรหัสวิชา ชื่อรายวิชา Section ภาคการศึกษา และปีการศึกษา
4. กรอกข้อมูลที่ระบบกำหนดให้ครบ
5. ตรวจว่าไม่มีวิชาซ้ำผิด Section หรือปี
6. กด **บันทึกข้อมูลรายวิชา**
7. เปิด **จัดการรายวิชา** เพื่อตั้งสมาชิก รหัสคลาส และเกณฑ์

หน้ารายวิชาสามารถสลับ Grid/List ได้ การสลับเปลี่ยนเฉพาะรูปแบบแสดงผล ไม่ควรทำให้ข้อมูลสองมุมมองแสดงพร้อมกัน

### 5.3 ศูนย์จัดการรายวิชา

| แถบ | รายละเอียด |
| --- | --- |
| **ข้อมูลรายวิชา** | ดูและแก้ข้อมูลที่นักศึกษาเห็นในหน้าวิชาและประวัติ |
| **เกณฑ์เข้าเรียน** | ตั้งจำนวนคาบ เวลามาสาย เวลาขาด และเปอร์เซ็นต์ขาดสูงสุด |
| **สมาชิก** | ดู ค้นหา นำเข้า และนำสมาชิกออกจากวิชา |
| **รหัสคลาส** | เปิด/ปิด ตั้งหมดอายุ หมุนรหัส และแสดงรหัสเต็มจอ |
| **ประวัติเข้าเรียน** | เปิดประวัติ แก้สถานะ จัดการรอบ และไปหน้ารายงาน |
| **พื้นที่อันตราย** | ลบรายวิชาและข้อมูลที่เกี่ยวข้องแบบย้อนกลับไม่ได้ |

ใช้ปุ่ม **กลับหน้ารายวิชา** เมื่อต้องการออกจากศูนย์จัดการ

### 5.4 ตั้งเกณฑ์การเข้าเรียน

1. เปิดวิชา > **เกณฑ์เข้าเรียน**
2. กด **แก้ไขเกณฑ์**
3. กำหนดจำนวนคาบทั้งหมด
4. กำหนดจำนวนนาทีหลังเปิดคาบที่จะถือว่า **มาสาย**
5. กำหนดจำนวนนาทีที่จะถือว่า **ขาดเรียน**
6. กำหนดเปอร์เซ็นต์ขาดสูงสุด
7. กด **บันทึกการตั้งค่า**

เกณฑ์ที่เปลี่ยนจะถูกนำไปใช้ในการคำนวณข้อมูลและรายงานตามตรรกะปัจจุบัน จึงควรแก้ก่อนเปิดคาบใหม่และตรวจรายงานอีกครั้ง หากแก้กลางภาคควรบันทึกเหตุผลและแจ้งนักศึกษาเพื่อให้ตรวจสอบย้อนหลังได้

### 5.5 จัดการรหัสคลาสและคำขอเข้าร่วม

1. เปิดวิชา > **รหัสคลาส**
2. เปิดใช้งานรหัสและตั้งวันหมดอายุเมื่อจำเป็น
3. กดขยายเต็มจอเพื่อแสดงให้นักศึกษา หรือส่งผ่านช่องทางที่ควบคุมได้
4. เปิดรายการ **คำขอเข้าร่วมรายวิชา**
5. กรองสถานะ รออนุมัติ/อนุมัติแล้ว/ปฏิเสธ/ยกเลิก/ทั้งหมด
6. ตรวจชื่อ อีเมล และรหัสนักศึกษาก่อนกดอนุมัติหรือปฏิเสธ
7. หากสงสัยว่ารหัสรั่ว ให้กดสร้างรหัสใหม่และยืนยันการหมุนรหัส

การหมุนรหัสทำให้รหัสเดิมใช้ไม่ได้ ควรแจ้งนักศึกษาที่ยังไม่ได้ส่งคำขอ

### 5.6 จัดการสมาชิกและนำเข้ารายชื่อ

1. เปิดวิชา > **สมาชิก**
2. ค้นหาด้วยชื่อ รหัสนักศึกษา หรืออีเมล
3. หากนำเข้าไฟล์ ให้เตรียม `.xlsx` หรือ `.csv` ตามรูปแบบที่ระบบรองรับ
4. เลือกไฟล์เพื่อเข้าสู่ขั้น **Preview**
5. ตรวจแถวที่ถูกต้อง รายการซ้ำ และรายการที่มีข้อผิดพลาด
6. แก้ไฟล์ต้นทางหากจำเป็น แล้ว Preview ใหม่
7. กด **Commit** เมื่อผลถูกต้อง

การนำสมาชิกออกจากรายวิชาไม่ใช่การลบบัญชีนักศึกษาออกจากระบบ ต้องตรวจชื่อวิชาและผู้ใช้ก่อนยืนยัน

### 5.7 เปิดคาบและแสดง Dynamic QR

1. เลือกรายวิชาที่ต้องการ
2. กดเปิดระบบเช็คชื่อ
3. ตรวจว่ารหัสวิชา Section และสถานะคาบถูกต้อง
4. แสดง Dynamic QR และกดขยายเต็มจอเมื่อใช้ในห้องเรียน
5. เฝ้าดูรายชื่อเข้าเรียนแบบ Realtime
6. หากเปลี่ยนแถบหรือไปหน้าอื่น session จะยังคงเปิดอยู่ที่ Backend/Database
7. ใช้ตัวบ่งชี้คาบที่กำลังเปิดบน Header เพื่อกลับไปยังหน้าคาบ
8. เมื่อหมดเวลา อาจารย์ต้องกดปิดคาบเองและยืนยัน

การปิด Browser ไม่ใช่การปิดคาบ ห้ามปล่อยคาบเปิดทิ้งไว้เพราะนักศึกษาอาจเช็คชื่อหลังเวลาที่ตั้งใจ

### 5.8 ใช้โหมด NFC

โหมดเครื่องสแกนบัตร NFC ใช้รับ UID จากเครื่องอ่านที่กำหนดและแสดงผู้เข้าเรียนล่าสุด อาจารย์ควรตรวจว่าบัตรผูกกับนักศึกษาถูกคน วางเครื่องอ่านในจุดที่ควบคุมได้ ดูชื่อหลังแตะทุกครั้ง และหยุดใช้พร้อมแจ้งผู้ดูแลหาก UID ซ้ำหรือชื่อไม่ตรง

### 5.9 จัดการประวัติการเข้าเรียน

1. เปิดวิชา > **ประวัติเข้าเรียน** > **เปิดประวัติเช็คชื่อ**
2. ค้นหานักศึกษาหรือเลือกคาบที่ต้องการ
3. ตรวจสถานะรายคนและสรุป มา/สาย/ขาด/คะแนน
4. แก้สถานะรายบุคคลเมื่อมีหลักฐาน
5. หากใช้การแก้แบบกลุ่ม ให้เลือกสถานะ **มาเรียน**, **มาสาย**, **ขาดเรียน** หรือ **ลา**
6. อ่านกล่องยืนยันที่แสดงจำนวนรายการและคาบก่อนดำเนินการ
7. ดาวน์โหลดรายงานเพื่อตรวจสอบหลังแก้ข้อมูล

การแก้แบบกลุ่มมีผลต่อทุกคนที่แสดงในขอบเขตนั้น ควรกรองรายการให้ถูกต้องและหลีกเลี่ยงการกดซ้ำระหว่างระบบกำลังบันทึก

### 5.10 จัดการรอบรายงานการเข้าเรียน

เมนูนี้รองรับการใช้วิชาเดิมข้ามภาคเรียนโดยไม่ลบประวัติเดิม

#### นำบางครั้งออกจากรายงาน

1. เปิด **จัดการรอบรายงานการเข้าเรียน**
2. เลือกคาบที่ปิดแล้ว หรือเลือกทั้งหมด
3. กด **นำ ... ครั้งออก**
4. ตรวจรายการและยืนยัน

คาบจะถูก Archive ออกจากรอบปัจจุบัน ไม่ได้ลบถาวร

#### คืนคาบที่พักไว้

1. ดูหัวข้อ **คาบที่พักไว้ในภาคเรียนปัจจุบัน**
2. ตรวจวันเวลาและเหตุผล
3. กด **คืนกลับ**
4. ยืนยัน คาบจะกลับเข้าในการคำนวณรายงาน

#### เริ่มภาคเรียนใหม่ด้วยรายงานเปล่า

1. เลือกภาคเรียนใหม่และปีการศึกษา
2. ตรวจว่าคาบเดิมและรายงานสำรองเรียบร้อย
3. กด **เริ่มรอบใหม่**
4. อ่านผลกระทบในกล่องยืนยันแล้วจึงยืนยัน

Rollover ทำให้รอบใหม่เริ่มจากรายงานเปล่า แต่เก็บประวัติเดิมไว้สำหรับตรวจสอบ ไม่ควรใช้การลบรายวิชาแทนการเริ่มรอบใหม่

### 5.11 ออกรายงาน

1. เปิด **รายงานการเข้าเรียน** หรือไปจากแถบประวัติของวิชา
2. เลือกรายวิชา ภาคเรียน และปีให้ถูกต้อง
3. เลือกรูปแบบ Excel, CSV หรือ PDF
4. รอให้ Browser สร้างและดาวน์โหลดไฟล์
5. เปิดไฟล์และตรวจรหัส/ชื่อวิชา Section ผู้สอน รายชื่อนักศึกษา จำนวนคาบ และสัญลักษณ์

PDF ถูกสร้างจากข้อมูลรายงานเดียวกับ Excel/CSV จึงควรให้ผลสรุปตรงกัน รายละเอียดคะแนนอยู่ในหัวข้อ 7

### 5.12 คำร้องของนักศึกษา

1. เปิด **ตั้งค่าระบบ** > **คำร้องของนักศึกษา**
2. เลือกรายการเพื่อดูข้อความและไฟล์แนบ
3. ใช้ปุ่มลด/เพิ่มขนาดตัวอักษรระหว่าง 14–22 px ตามความสะดวก
4. เปิดตัวอย่าง PDF/รูป หรือกด **ดาวน์โหลด** ผ่านลิงก์ที่ Backend อนุญาต
5. พิมพ์คำตอบและแนบไฟล์เมื่อจำเป็น
6. กด **เสร็จสิ้น** เมื่อดำเนินการครบ

อาจารย์เข้าถึงเฉพาะคำร้องของวิชาที่รับผิดชอบ ไฟล์อยู่ใน private Storage และต้องผ่าน Backend ก่อนเปิดหรือดาวน์โหลด ห้ามส่งต่อนอกวัตถุประสงค์

### 5.13 ขอสิทธิ์ผู้ดูแลชั่วคราว

1. เปิด **ตั้งค่าระบบ** > **สิทธิ์ผู้ดูแลชั่วคราว**
2. ส่งเหตุผลที่ชัดเจนและรอผู้ดูแลถาวรอนุมัติ
3. หลังอนุมัติ ให้ตั้ง PIN 6 หลักภายในเวลาที่ระบบกำหนด
4. ใช้ PIN เปิดสิทธิ์ครั้งละช่วงเวลาที่หน้าจอแจ้ง
5. ทำเฉพาะงานที่ได้รับมอบหมาย
6. ออกจากโหมดผู้ดูแลเมื่อเสร็จ

PIN ผูกกับบัญชีและการอนุมัติ ไม่ควรใช้ PIN ที่เดาง่าย บันทึกลงเอกสารสาธารณะ หรือส่งให้ผู้อื่น ผู้ดูแลถาวรสามารถเพิกถอนได้

### 5.14 ลบรายวิชาอย่างปลอดภัย

1. ส่งออกและตรวจรายงานก่อน
2. เปิด **พื้นที่อันตราย**
3. ตรวจรหัสวิชา ภาคเรียน และ Section
4. อ่านว่าการลบมีผลต่อสมาชิก คาบ ประวัติ คำร้อง และรหัสคลาส
5. ดำเนินการต่อเฉพาะเมื่อแน่ใจ เพราะย้อนกลับไม่ได้

หากต้องการเพียงเริ่มภาคใหม่ ให้ใช้ Rollover ไม่ใช่ลบรายวิชา

## 6. คู่มือสำหรับผู้ดูแลระบบถาวร

### 6.1 ภาพรวมเมนูผู้ดูแล

| เมนู | หน้าที่ |
| --- | --- |
| **ภาพรวมระบบ** | ดูจำนวนผู้ใช้ รายวิชา และสรุปการทำงาน |
| **จัดการผู้ใช้งาน** | ค้นหา เรียง แก้ข้อมูล เปลี่ยน role และลบผู้ใช้ |
| **จัดการรายวิชา** | ค้นหา ดูเจ้าของ แก้เกณฑ์ แก้ข้อมูล และลบวิชา |
| **จัดการการลงทะเบียน** | ลงทะเบียน/แทนที่ใบหน้าและผูก NFC ตามสิทธิ์ |
| **ตรวจสอบ Log (Audit)** | ค้นและตรวจการกระทำสำคัญในระบบ |
| **ออกรายงาน (Export)** | ค้นวิชา สลับ List/Grid และส่งออกรายงาน |
| **อนุมัติสิทธิ์ชั่วคราว** | อนุมัติ ปฏิเสธ และเพิกถอนสิทธิ์อาจารย์ เฉพาะผู้ดูแลถาวร |

ผู้ดูแลชั่วคราวอาจไม่เห็นหรือใช้งานเมนูความเสี่ยงสูงบางรายการ และมีปุ่มกลับสู่ระบบอาจารย์เมื่อจบงาน

### 6.2 ภาพรวมระบบ

1. เปิด **ภาพรวมระบบ (System Overview)**
2. ตรวจจำนวนผู้ใช้และรายวิชา
3. ดูความผิดปกติ เช่น จำนวนลดลงมากหรือข้อมูลไม่โหลด
4. หากข้อมูลผิด ให้ตรวจ API/Database ก่อนแก้รายการจริง

หน้าภาพรวมเป็นข้อมูลช่วยตรวจสอบ ไม่ใช้แทน Audit Log สำหรับสืบค้นเหตุการณ์เฉพาะ

### 6.3 จัดการผู้ใช้งาน

1. เปิด **จัดการผู้ใช้งานและสิทธิ์ (User Management)**
2. ค้นด้วยชื่อ-นามสกุลหรือรหัสนักศึกษา
3. กดหัวคอลัมน์ Role เพื่อเรียงตามสิทธิ์
4. กดแก้ไขที่ผู้ใช้เป้าหมาย
5. ตรวจชื่อ อีเมล รหัสนักศึกษา ชั้นปี และ role
6. แก้เฉพาะข้อมูลที่ได้รับอนุญาต แล้วบันทึก
7. ตรวจผลในตารางและ Audit Log เมื่อเป็นการเปลี่ยนสิทธิ์

ก่อนเปลี่ยน `student`, `teacher` หรือ `admin` ต้องยืนยันตัวตนและเหตุผล การเปลี่ยน role ผิดอาจเปิดเผยข้อมูลหรือทำให้ผู้ใช้เข้าเมนูเดิมไม่ได้

#### ลบผู้ใช้

1. ค้นและเปิดผู้ใช้ให้ถูกคน
2. ตรวจข้อมูลที่เชื่อมโยง เช่น วิชา ประวัติ ใบหน้า NFC และคำร้อง
3. อ่านกล่องยืนยัน
4. ลบเฉพาะเมื่อมีนโยบายรองรับและมีข้อมูลสำรองที่จำเป็น

### 6.4 จัดการรายวิชาทั้งระบบ

1. เปิด **จัดการรายวิชา**
2. ค้นด้วยรหัสวิชา ชื่อวิชา หรือชื่อผู้สอน
3. ตรวจเจ้าของวิชา Section ภาคเรียน และปี
4. ใช้ปุ่มตั้งค่าเกณฑ์หรือแก้ข้อมูลตามงานที่ได้รับ
5. หากลบ ให้ตรวจผู้สอนและรายงานสำรองก่อนยืนยัน

ผู้ดูแลไม่ควรแก้เกณฑ์แทนอาจารย์โดยไม่มีหลักฐานหรือคำขอ เพราะอาจเปลี่ยนผลคำนวณและรายงาน

### 6.5 จัดการการลงทะเบียนใบหน้าและ NFC

หน้า **ระบบลงทะเบียน (Enrollment)** เป็นงานความเสี่ยงสูง ใช้เมื่อจำเป็นต้องลงทะเบียนหรือแก้ข้อมูลแทนนักศึกษา

#### ใบหน้า

1. กรอกรหัสนักศึกษาให้ครบ
2. ตรวจชื่อบัญชีเป้าหมาย
3. ดำเนินการถ่ายภาพและ Liveness ตามขั้นตอนที่หน้าจอกำหนด
4. อ่านข้อความให้ชัดว่าเป็นการลงทะเบียนใหม่หรือแทนที่ข้อมูลเดิม
5. ตรวจผลและ Audit Log

#### NFC

1. กรอกรหัสนักศึกษา
2. ให้ผู้ใช้แตะบัตรกับเครื่องอ่านที่ควบคุมได้
3. ตรวจ UID และชื่อก่อนบันทึก
4. หาก UID ถูกใช้แล้ว ให้หยุดและตรวจเจ้าของเดิม ห้ามย้ายโดยเดา

ไม่ควรคัดลอก face embedding หรือ UID ลงในเอกสารภายนอก

### 6.6 ตรวจ Audit Log

1. เปิด **ตรวจสอบ Log (Audit)**
2. ค้นด้วยผู้ดำเนินการ การกระทำ หรือเป้าหมาย
3. ตรวจวันเวลา actor action target และรายละเอียดที่ระบบอนุญาต
4. ใช้ปุ่มโหลดใหม่หากต้องการเหตุการณ์ล่าสุด
5. บนโทรศัพท์ ระบบแสดงเป็น Card; จอใหญ่แสดงตารางแบบ Responsive

Audit Log ใช้สำหรับตรวจสอบ ไม่ควรแก้ไขย้อนหลัง และห้ามนำ token, biometric template หรือข้อมูลส่วนบุคคลไปใส่ในช่องค้นหาหรือรายงานที่ไม่จำเป็น

### 6.7 ออกรายงานทั้งระบบ

1. เปิด **ออกรายงานการเช็คชื่อ**
2. ค้นด้วยรหัสวิชา ชื่อวิชา หรือชื่ออาจารย์ผู้สอน
3. เลือกมุมมอง **List** หรือ **Grid** อย่างใดอย่างหนึ่ง
4. ตรวจวิชา เทอม ปี Section และผู้สอน
5. เลือก Excel, CSV หรือ PDF
6. ตรวจไฟล์ที่ได้ตามหัวข้อ 7

การสลับ List/Grid มีผลเฉพาะการแสดงผล ไม่เปลี่ยนข้อมูลและไม่ควรแสดงสองรูปแบบซ้อนกัน

### 6.8 อนุมัติสิทธิ์ผู้ดูแลชั่วคราว

1. เปิด **คำขอสิทธิ์ผู้ดูแลชั่วคราว**
2. ตรวจชื่อ อีเมล เหตุผล และเวลาที่ส่งคำขอ
3. หากปฏิเสธ ให้ระบุเหตุผลที่นำไปแก้ไขได้
4. หากอนุมัติ อ่านเวลาสำหรับตั้ง PIN และอายุของ grant ในกล่องยืนยัน
5. ติดตามรายชื่อผู้ได้รับอนุมัติและเวลาที่ใช้งานล่าสุด
6. กด **เพิกถอนสิทธิ์** เมื่อหมดความจำเป็น อุปกรณ์สูญหาย หรือสงสัยว่า PIN รั่วไหล

การอนุมัติไม่เปลี่ยน role ถาวรของอาจารย์ และควรให้สิทธิ์ตามหลักน้อยที่สุดเท่าที่จำเป็น

## 7. สถานะการเข้าเรียน คะแนน และรายงาน

### 7.1 ความหมายของสถานะ

| สถานะ | ความหมายทั่วไป | คะแนนรายงาน | สัญลักษณ์ในตาราง |
| --- | --- | ---: | --- |
| มาเรียน (`present`) | เช็คชื่อผ่านภายในช่วงมาเรียน | 1.0 | `1` |
| มาสาย (`late`) | เช็คชื่อผ่านหลังเกณฑ์มาสายแต่ก่อนเกณฑ์ขาด | 0.5 | `/` |
| ขาดเรียน (`absent`) | ไม่มีการเช็คชื่อที่ผ่านหรือเกินเกณฑ์ขาด | 0 | `X` |
| ลา (`leave`) | ผู้สอนบันทึกการลาตามหลักฐาน | ขึ้นกับการนำไปใช้ของรายวิชา | แสดงตามรูปแบบรายงานปัจจุบัน |

เวลา **มาสายหลังจาก** และ **ขาดเรียนหลังจาก** มาจากเกณฑ์ของแต่ละวิชา จึงอาจไม่เท่ากัน

### 7.2 สิ่งที่อยู่ในรายงาน

- รหัสและชื่อรายวิชา
- Section ภาคเรียน และปีการศึกษา
- ชื่อผู้สอน
- รหัสและชื่อนักศึกษา
- คอลัมน์คาบ/สัปดาห์
- จำนวนมาเรียน มาสาย ขาด และคะแนนรวม
- คำอธิบายสัญลักษณ์ `1`, `/`, `X`
- หมายเหตุหรือผลสรุปตามเกณฑ์วิชา
- วันเวลาที่สร้างเอกสาร

Excel เหมาะกับการตรวจและคำนวณต่อ CSV เหมาะกับการนำข้อมูลไปใช้ในระบบอื่น และ PDF เหมาะกับการอ่าน/พิมพ์โดยคงรูปแบบ ผู้ใช้ต้องตรวจความถูกต้องก่อนใช้เป็นเอกสารทางการ

### 7.3 เมื่อมีการแก้เกณฑ์

1. บันทึกเหตุผลและเวลาที่เปลี่ยน
2. โหลดหน้าประวัติใหม่
3. ตรวจสถานะตัวอย่างอย่างน้อยหนึ่งคนในคาบก่อนและหลังเกณฑ์
4. สร้างรายงานใหม่ ห้ามใช้ไฟล์เก่าที่ดาวน์โหลดก่อนเปลี่ยน
5. เปรียบเทียบจำนวนและคะแนนรวม

หากต้องการตรึงกติกาเดิมสำหรับคาบที่ผ่านมา ควรกำหนดนโยบายรายวิชาให้ชัดก่อนเปลี่ยน เพราะรายงานปัจจุบันใช้ข้อมูลและเกณฑ์ที่ระบบเรียกในขณะสร้างรายงาน

## 8. ความปลอดภัยและความเป็นส่วนตัว

### 8.1 หลักปฏิบัติสำหรับทุกคน

1. ใช้บัญชีของตนเองเท่านั้น
2. ออกจากระบบเมื่อใช้อุปกรณ์ร่วมกัน
3. ไม่ส่ง QR, PIN, token หรือข้อมูลชีวมิติให้ผู้อื่น
4. ไม่ใช้ภาพถ่าย วิดีโอ replay หรือ challenge ของบุคคลอื่น
5. ตรวจโดเมนเว็บไซต์ก่อนอนุญาตกล้องหรือเข้าสู่ระบบ
6. แจ้งเหตุทันทีเมื่อสงสัยว่าบัญชีหรืออุปกรณ์ถูกใช้โดยผู้อื่น

### 8.2 ข้อมูลใบหน้าและ Liveness

- ระบบใช้ Face Landmarker ใน Browser เพื่อช่วยติดตามใบหน้า
- Backend ตรวจหลักฐานใหม่ ไม่เชื่อผลจาก Browser เพียงอย่างเดียว
- Hybrid Liveness ใช้ Passive 3 เฟรม คำสั่งสุ่ม และ Recovery frame
- Passive PAD ช่วยลดความเสี่ยงภาพพิมพ์ หน้าจอ และวิดีโอทั่วไป
- Challenge ผูกกับผู้ใช้และการทำรายการ ใช้ครั้งเดียว และมีเวลาหมดอายุ
- รูปบัตรและเฟรม Liveness ไม่ถูกเก็บเป็นภาพเช็คชื่อถาวรตามขอบเขตระบบ

ระบบกล้อง RGB ไม่สามารถรับประกันการป้องกันการปลอมแปลงทุกชนิดหรือแทนมาตรฐานรับรองเฉพาะทางได้ ต้องทดสอบกับอุปกรณ์ แสง และกลุ่มผู้ใช้จริงก่อนใช้งานสำคัญ

### 8.3 ไฟล์แนบคำร้อง

- เก็บใน Supabase Storage แบบ private
- เปิดตัวอย่างและดาวน์โหลดผ่าน Backend ที่ตรวจสิทธิ์
- จำกัดชนิด จำนวน และขนาดไฟล์
- ไม่รับ SVG เพื่อลดความเสี่ยงเนื้อหา active
- รูปภาพถูกทำให้เป็นภาพนิ่งและลบ metadata ก่อนจัดเก็บ
- อาจารย์เห็นเฉพาะคำร้องของวิชาที่รับผิดชอบ

### 8.4 หน้าที่ของผู้ดูแล

- ใช้ publishable/anon key เฉพาะฝั่งหน้าเว็บตามการตั้งค่าระบบ
- เก็บ service-role key และ secret ทั้งหมดไว้ฝั่ง Backend เท่านั้น
- ไม่คัดลอกค่า secret ลง Log, Screenshot หรือเอกสาร
- ใช้ Row Level Security และการตรวจ role ที่ Backend เป็นชั้นควบคุมสิทธิ์
- เพิกถอน session, PIN, temporary grant หรือ NFC เมื่อสงสัยรั่วไหล

## 9. การแก้ปัญหาเบื้องต้น

| อาการ | สาเหตุที่เป็นไปได้ | วิธีตรวจและแก้ |
| --- | --- | --- |
| Login แล้ววนกลับหน้าเดิม | Redirect URL/session/cookie ไม่สมบูรณ์ | ตรวจว่าเปิด URL production ที่ถูกต้อง อนุญาต Cookie แล้วออกและ Login ใหม่ |
| Login สำเร็จแต่โหลดโปรไฟล์ไม่ได้ | Backend, CORS, session หรือเครือข่าย | กดลองใหม่ ตรวจเวลาและ HTTP status แล้วแจ้งผู้ดูแล |
| `/auth/me` ตอบ 401 | Session หมดอายุหรือ token ใช้ไม่ได้ | ออกจากระบบและเข้าสู่ระบบใหม่ |
| API ถูก CORS block | Backend ไม่อนุญาต exact origin หรือ preflight ผิด | ผู้ดูแลตรวจ Frontend origin, CORS middleware, Nginx/tunnel และ `OPTIONS`; ห้ามใช้ `no-cors` |
| กล้องไม่เปิด | ไม่อนุญาตกล้อง ไม่ใช่ HTTPS หรือกล้องถูกใช้งาน | เปิด permission ปิดแอปอื่น โหลดหน้าใหม่ และเลือกกล้องอีกครั้ง |
| ภาพเบลอ | เลนส์สกปรก แสงน้อย โฟกัสผิด หรือซูมมาก | เช็ดเลนส์ เพิ่มแสง เลือกเลนส์/ความละเอียด และลด Zoom |
| Header/Nav ยังอยู่ขณะเปิดกล้อง | Bundle เก่าหรือ PWA cache เก่า | ปิดหน้ากล้อง Refresh และเปิดใหม่ หากยังพบให้แจ้งเวอร์ชัน/เวลา |
| เตรียมระบบตรวจใบหน้าไม่สำเร็จ | โมเดล/WASM โหลดไม่ครบ เครือข่ายช้า หรือ Browser จำกัด | รอการโหลดครั้งแรก ตรวจเครือข่าย กดลองใหม่ และใช้ Browser รุ่นปัจจุบัน |
| iPhone Chrome มีปัญหาแต่ Safari ใช้ได้ | Browser บน iOS ใช้ WebKit และอาจมี cache/permission ต่างกัน | อัปเดต iOS/Chrome ล้าง site data อนุญาตกล้องใหม่ หรือใช้ Safari ชั่วคราวแล้วแจ้งรุ่น |
| OCR ไม่พบรหัส | บัตรไม่เต็มภาพ เบลอ เอียง หรือสะท้อนแสง | ถ่าย/เลือกภาพใหม่ให้รหัสชัดและตรง |
| Liveness ไม่ผ่าน | หลายใบหน้า แสงเปลี่ยน ทำคำสั่งผิด หรือเฟรมซ้ำ | อยู่คนเดียวในกรอบ ใช้แสงนิ่ง ทำเฉพาะคำสั่ง และกดลองใหม่ |
| QR อ่านไม่ได้ | QR เล็ก เบลอ สว่างจ้า หรือกล้องผิดเลนส์ | ใช้กล้องหลัง ขยาย QR ลดแสงสะท้อน และถือให้นิ่ง |
| QR หมดอายุ | ใช้ภาพเก่าหรือ QR หมุนแล้ว | สแกน QR ปัจจุบันจากจออาจารย์ |
| Backend แจ้งสิทธิ์สแกนใบหน้าไม่ครบ | Contract Frontend/Backend คนละรุ่น หรือ challenge ไม่ครบ | ผู้ดูแลตรวจ deployment ของทั้งสองส่วนและ response ของ endpoint ห้ามแก้ payload เอง |
| เช็คชื่อซ้ำไม่ได้ | Challenge เป็นแบบใช้ครั้งเดียวหรือมีรายการแล้ว | ดูประวัติ หากข้อมูลผิดให้ส่งคำร้อง ไม่ควรยิง request ซ้ำ |
| ไฟล์แนบเปิดไม่ได้ | หมดสิทธิ์ ลิงก์ชั่วคราวหมดอายุ หรือชนิดไฟล์ไม่รองรับ | โหลดคำร้องใหม่ ตรวจชนิด/ขนาด แล้วดาวน์โหลดอีกครั้ง |
| Export ไม่ดาวน์โหลด | Browser block download หรือข้อมูลยังโหลดไม่ครบ | อนุญาต download รอข้อมูล เลือกรูปแบบใหม่ และลองอีกครั้ง |
| List/Grid แสดงซ้อนกัน | Frontend bundle เก่าหรือ state ผิด | Refresh แบบไม่ใช้ cache แล้วแจ้งหน้าและขั้นตอนที่เกิด |
| กล่องยืนยันอยู่หลัง Modal | Bundle เก่าหรือชั้น Portal ผิด | Refresh เพื่อรับรุ่นล่าสุด แล้วแจ้งเมนู/การกระทำหากยังเกิด |
| Session เช็คชื่อหายจากหน้าจอ | เปลี่ยนบัญชี เครือข่ายขาด หรือคาบถูกปิด | ตรวจตัวบ่งชี้ Active session และโหลดใหม่; ตรวจ Backend ก่อนเปิดคาบซ้ำ |
| ข้อมูลเฉพาะโทรศัพท์ผิด | Cache, safe-area, Browser หรือหน้าจอเฉพาะรุ่น | แจ้งรุ่นเครื่อง OS Browser ขนาดหน้าจอ เวลา และภาพหน้าจอที่ไม่มีข้อมูลลับ |

### ข้อมูลที่ควรแนบเมื่อแจ้งปัญหา

- บทบาทและชื่อเมนูที่เกิดปัญหา
- วันเวลาและเขตเวลา
- ขั้นตอนก่อนเกิดปัญหา
- ข้อความผิดพลาดแบบเต็ม
- รุ่นอุปกรณ์ ระบบปฏิบัติการ และ Browser
- HTTP status หรือ Request ID ถ้ามี
- ภาพหน้าจอที่ปิดบังชื่อ อีเมล รหัสนักศึกษา และข้อมูลลับแล้ว

ห้ามแนบ access token, Cookie, service key, PIN, ภาพบัตร หรือภาพใบหน้า

- [ ] ชื่อ รหัส และชั้นปีถูกต้อง
- [ ] วิชาที่ลงทะเบียนถูกต้อง
- [ ] สถานะใบหน้าพร้อม
- [ ] กล้องเปิดได้และภาพชัด
- [ ] หน้าแรกแสดงว่าระบบตรวจใบหน้าพร้อมก่อนสแกน QR
- [ ] ทราบวิธีส่งคำร้องเมื่อประวัติผิด

### 10.2 อาจารย์

- [ ] รหัสวิชา Section ภาคเรียน และปีถูกต้อง
- [ ] สมาชิกและคำขอเข้าวิชาได้รับการตรวจแล้ว
- [ ] เกณฑ์มาสาย ขาด และจำนวนคาบถูกต้อง
- [ ] Dynamic QR แสดงเต็มจอและอ่านได้จากจุดใช้งาน
- [ ] Realtime feed หรือ NFC ทำงาน
- [ ] ปิดคาบหลังหมดเวลา
- [ ] ตรวจรายงานตัวอย่างและสำรองก่อน Rollover/ลบวิชา

### 10.3 ผู้ดูแลระบบ

- [ ] บทบาทผู้ใช้ถูกต้องและใช้สิทธิ์น้อยที่สุด
- [ ] Backend health และ Supabase เชื่อมต่อได้
- [ ] CORS อนุญาตเฉพาะ origin ที่ใช้งานจริง
- [ ] Storage ไฟล์แนบเป็น private และดาวน์โหลดผ่าน Backend
- [ ] Audit Log โหลดและค้นหาได้
- [ ] ทดสอบ Export ทั้ง Excel, CSV และ PDF
- [ ] ตรวจขั้นตอนอนุมัติ/เพิกถอน temporary admin
- [ ] ไม่มี secret หรือข้อมูลบุคคลรั่วใน Log และเอกสาร

## 11. คำศัพท์ที่ใช้ในระบบ

| คำศัพท์ | ความหมาย |
| --- | --- |
| Dynamic QR | QR ที่เปลี่ยนตามเวลาและผูกกับคาบที่กำลังเปิด |
| Session | รอบเช็คชื่อของรายวิชาหนึ่งครั้ง ตั้งแต่เปิดจนปิด |
| Liveness | การตรวจว่าผู้หน้ากล้องเป็นบุคคลที่อยู่จริงในขณะนั้น |
| Passive PAD | การตรวจ Presentation Attack จากภาพโดยไม่ให้ผู้ใช้ทำหลายขั้นตอน |
| Hybrid Liveness | Passive PAD ร่วมกับคำสั่งสุ่มและ Recovery frame |
| Face embedding | ชุดตัวเลขแทนลักษณะใบหน้าที่ใช้เปรียบเทียบ ไม่ใช่ไฟล์ภาพปกติ |

| Audit Log | ประวัติการกระทำสำคัญเพื่อการตรวจสอบ |
